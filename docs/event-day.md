# 当日の運用手順

## 事前準備（前日まで）
### レジPC（Ubuntu）のネットワーク設定
1. ファイアウォールでポート3000を開ける：
   ```bash
   sudo ufw allow 3000/tcp
   sudo ufw status        # 3000/tcp ALLOW が出ていればOK（ufw が inactive なら何もしなくてよい）
   ```
2. テザリングにつないで、IPアドレスを確認：`hostname -I`
3. スマホから `http://<レジPCのIP>:3000` が開けることを確認
4. 当日に画面が消えたり止まったりしないよう、設定 → 電源 で**自動サスペンドと画面ブランクをオフ**にする
   - ノートPCの場合は「蓋を閉じたときにサスペンドしない」設定も確認（開けたまま使うなら不要）

### お客さん向け呼び出し状況ページ（Cloudflare、初回だけ）
1. Cloudflare のアカウントを作る（無料）
2. 公開する：
   ```bash
   cd ~/dev/taiyaki-pos/cloud
   npm install
   npx wrangler login              # ブラウザでCloudflareにログイン
   npx wrangler secret put PUSH_TOKEN   # 長いランダムな文字列を入力（例：openssl rand -hex 24 の結果）
   npm run deploy                  # 表示された https://taiyaki-status.<名前>.workers.dev がページのURL
   ```
3. レジPCの `~/dev/taiyaki-pos/.env.public` に書く（このファイルはコミットしない）：
   ```
   PUBLIC_STATUS_URL=https://taiyaki-status.<名前>.workers.dev
   PUBLIC_STATUS_TOKEN=<2で入力したのと同じ文字列>
   ```
4. 番号札とポスターを作って印刷する：`npm run tickets -- 1 300`（`.env.public` のURLを使う）→ `print/tickets.html` をブラウザで開き、A4で印刷して点線で切る
   - 番号札は番号ごとにQRコードが違う（読み取ると自分の番号のページが開く）。注文の番号と同じ番号の札を渡す
   - 当日 `npm run db:reset` をしたら番号は1から振り直しになるので、札も1番から使う

### その他
- [ ] テザリング役のスマホを決める（充電しながら使う。モバイルバッテリーを用意）
- [ ] レジPC・キッチンPCの電源を確保（延長コード）
- [ ] 各端末でURLをブックマークしておく
- [ ] 本番ビルドしておく：`npm run build`
- [ ] 動作確認：`npm run start` のまま別ターミナルで `npm run load-test -- 100`（100件注文して応答時間と番号の重複を表示）
- [ ] DBを初期化：`npm run db:reset`（テストデータを消す。サーバーは止めてから実行し、あとで起動し直す）
- [ ] 予備の紙：番号札、注文メモ用紙、ペン
- [ ] 係の人の練習：`npm run practice` で起動して、レジ・キッチン・呼び出し表示を触ってもらう（練習用DBなので本番には残らない。終わったら Ctrl+C）

## 当日の開店手順
1. テザリング役のスマホでテザリングをON
2. レジPC・キッチンPC・スタッフのスマホをテザリングに接続
3. レジPCでターミナルを開き、`cd ~/dev/taiyaki-pos && npm run event`
   - サーバー・お客さん向けページへの送信・自動バックアップがまとめて起動する（ビルドがなければ先に作る）
   - 画面に各端末で開くURLが出る。「LANのIPアドレスが見つかりません」と出たら、テザリングにつながっていない
   - このターミナルは閉じずに置いておく（落ちたものは自動で再起動する）
4. 表示されたURLを各端末で開く（管理画面 `/admin` にも出ている）。レジ・キッチン・呼び出し表示は、開いたら**画面を1回タップ**する（画面が消えなくなる・キッチンは注文の音が鳴るようになる。画面下のオレンジの帯が消えればOK）
   - レジPC → `/register`
   - キッチンPC → `/kitchen`
   - 呼び出し表示用のスマホ → `/display`
   - 責任者のスマホ → `/admin`
5. お客さん向けページ用に、テザリングのモバイルデータをONにしておく
6. 試しに1件注文 → 完成 → 渡した まで流して、お客さん向けページにも出ることを確認し、取り消しておく

## 営業中
- バックアップは自動（10分ごとに `backups/` へCSVとDBのコピー）。USBメモリにも残したいときは、起動時に `BACKUP_DIR=/media/<USBの場所>/taiyaki npm run event`
- 念のため、責任者は数時間に1回 `/admin` からもCSVをダウンロードしておく
- 材料が尽きそうな味は、メニュー表に「残りわずか」「売り切れ」を貼り、レジで口頭でも伝える（アプリに売り切れ機能はない）

## トラブル時
| 症状 | 対応 |
|---|---|
| 他の端末で画面上部に「接続エラー」 | テザリングが切れていないか確認 → 端末をつなぎ直す |
| レジPCのIPが変わった | `/admin` で新しいURLを確認し、各端末で開き直す |
| サーバーが落ちた | `npm run event` のターミナルに「⚠ サーバーが止まりました」と出て、自動で再起動する（データは残る）。ターミナルごと閉じてしまったら `npm run event` で起動し直す |
| お客さん向けページに「更新されていません」 | `npm run event` のターミナルに `[送信]` のエラーが出ていないか、テザリングのモバイルデータがONか確認。直らなくても営業は続けられる（呼び出し表示を見てもらう） |
| 画面下にオレンジの「1回タップしてください」が出ている | 画面のどこかを1回タップ（別のアプリから戻ったときなどに出る） |
| キッチンで新しい注文の音が鳴らない | 画面を1回タップしたか、「新しい注文の音」がオンか、端末の音量を確認 |
| ミニゲームのランキングに不適切な名前が出た | `npm run ranking` で番号を確かめて、`npm run ranking -- remove 番号` で消す |
| どうしても復旧しない | **紙運用に切り替え**：番号札は最後に発行した番号の続きから手書き、注文は紙に記録し、あとでまとめて入力 |

## 閉店後
1. `/admin` で売上・金券枚数を確認し、**実際の金券の枚数と照合**
2. `npm run event` のターミナルで Ctrl+C（最後のバックアップを取ってから全部止まる）
3. `backups/` の最新のCSVとDB（または `npm run backup` でその場で取ったもの）を共有フォルダとUSBにコピーして保管
