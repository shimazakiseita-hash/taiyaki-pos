# 仕様書 — たい焼き屋台 注文管理アプリ

## 1. 運用の前提
| 項目 | 内容 |
|---|---|
| 開催 | 寮祭当日の1日のみ |
| 提供方式 | 先に会計 → 呼び出し番号を発行 → 焼き上がったら番号で呼んで受け渡し |
| 支払い | 100円券の金券のみ（お釣りは発生しない） |
| 端末 | レジPC 1台（サーバー兼用）、キッチンPC 1台、スタッフの個人スマホ数台 |
| ネットワーク | スマホのテザリングで作るローカルネットワーク。インターネット接続は不要 |
| 販売目標 | 300個（味ごとの販売数に上限は設けない） |

## 2. メニューと料金
| id | 表示名 | テーマ色 |
|---|---|---|
| anko | あんこ | 赤 |
| custard | カスタード | 黄 |
| matcha | 抹茶 | 緑 |
| choco | チョコ | 茶 |

- 味ごとの仕込み上限・売り切れ判定はない（数が当日決まっていないため）。材料が尽きたら口頭で案内する

- 単品200円、**味を問わず3個で500円**
- 1注文の合計金額 = `floor(総個数 / 3) * 500 + (総個数 % 3) * 200`
  - 例：1個=200、2個=400、3個=500、4個=700、5個=900、6個=1000
- 金券枚数 = 合計金額 / 100
- 1注文の総個数は 1〜20 個

## 3. 注文の状態遷移
```
waiting（焼き待ち） → ready（完成・呼び出し中） → served（受け渡し済み）
waiting → cancelled（取り消し）
ready → waiting（「完成」の押し間違いを戻す）
served → ready（「渡した」の押し間違いを戻す）
```
上記以外の遷移はエラー（409）。

## 4. データモデル（SQLite）
```sql
CREATE TABLE orders (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  number      INTEGER NOT NULL UNIQUE,      -- 呼び出し番号（1からの連番）
  status      TEXT NOT NULL CHECK (status IN ('waiting','ready','served','cancelled')),
  total_qty   INTEGER NOT NULL,
  amount      INTEGER NOT NULL,             -- 円
  created_at  TEXT NOT NULL,                -- ISO8601
  ready_at    TEXT,
  served_at   TEXT,
  cancelled_at TEXT
);
CREATE TABLE order_items (
  order_id INTEGER NOT NULL REFERENCES orders(id),
  flavor   TEXT NOT NULL CHECK (flavor IN ('anko','custard','matcha','choco')),
  qty      INTEGER NOT NULL CHECK (qty > 0),
  PRIMARY KEY (order_id, flavor)
);
CREATE TABLE settings (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL                        -- JSON文字列
);
```
- 呼び出し番号：`SELECT COALESCE(MAX(number),0)+1 FROM orders` を注文INSERTと同一トランザクションで取得
- settings：`target_qty`（300）
- WALモードを有効にする

## 5. 集計の定義
- **販売数**：status が cancelled 以外の注文の個数合計（味別・全体）
- **売上**：cancelled 以外の amount 合計。**金券枚数**＝売上/100（閉店後の金券と照合する）
- **焼くべき数**：status = waiting の注文の個数合計（味別）
- **平均待ち時間**：直近10件の served 注文の `served_at - created_at` の平均

## 6. 画面
すべて `http://<レジPCのIP>:3000/<パス>` でアクセス。トップ `/` は各画面へのリンク集。

### 6.1 レジ `/register`（レジPC）
- 味ボタン4つ（テーマ色、大きく）。タップで+1、各味に−ボタン
- 画面右側：選択中の内訳、総個数、**合計金額と「金券 ◯枚」を特大表示**
- 「確定」→ 注文作成 → 発行された**呼び出し番号を画面いっぱいに表示**（番号札に書く／伝える用）→ 「次のお客さん」で入力画面に戻る
- 「クリア」で入力中の内容を破棄
- 直近の注文5件を表示し、waiting のものは取り消しできる（確認ダイアログあり）

### 6.2 キッチン `/kitchen`（キッチンPC）
- 上部：**味ごとの「焼くべき数」**を大きく表示
- 下部：waiting の注文を古い順にカード表示（番号・経過時間・味別個数）
  - 経過10分以上のカードは強調表示
  - 「完成」ボタン → ready
- 右側：ready の注文一覧。「渡した」→ served、「戻す」→ waiting
- 最近 served にした注文を3件表示し、「戻す」で ready に戻せる
- 新しい注文が入ったら「ピンポン」と鳴らす（Web Audio で合成、音声ファイルなし）。「新しい注文の音：オン／オフ」で切り替え

### 6.3 呼び出し表示 `/display`（お客さん向け、スマホやPCの別ウィンドウ）
- ready の番号を特大で表示（「お呼び出し中」）
- waiting の番号を小さく表示（「焼いています」）
- 操作ボタンなし。新しく ready になった番号は数秒間ハイライト

### 6.4 管理 `/admin`（責任者のスマホ）
- 売上金額・金券枚数・販売数（全体と味別）・目標300個に対する進捗バー
- 現在の待ち件数と平均待ち時間
- 全注文のCSVダウンロード（バックアップ・事後集計用）
- サーバーのLAN上のURL表示（他の端末をつなぐとき用）

### 6.5 お客さん向け呼び出し状況ページ（任意・クラウド）
- お客さんが自分のスマホ（モバイル回線）で開く。Cloudflare Workers 上に置く（`cloud/`）
- 入口は2つ：屋台に貼るポスターのQR（番号なし）と、**番号札ごとのQR**（`?n=12` つき。読み取るだけで自分の番号が入る）。番号札は 1〜300 番くらいを事前に印刷しておく（`npm run tickets`）
- 見た目は店内の呼び出し表示 `/display` とそろえる（ロゴ・青海波・浮き輪の番号）。見出しだけ筆文字（Yuji Syuku、使う文字だけに切り出して配信）
- **自分の番号**：浮き輪の中に番号、状態（焼いています／できあがり！／見当たらない）と「前にあと◯件」（自分より小さい焼き待ち番号の数）、「目安：あと約◯分」（（前の件数＋1）× 完成のペース。ペースは直近10件の完成の間隔の平均で、完成が3件未満のうちは出さない）。たい焼きが受け取り口へ泳いでいく進み具合のバー（最初に見たときの件数を基準）
  - 見ている間にできあがったら、浮き輪が揺れて水しぶき、タブのタイトルを「【できあがり！】」に変え、対応端末（Android）は振動する
  - 番号は端末に記憶する。「番号を変える」で入力し直せる
- **全体**：「お呼び出し中」の番号（新しく呼んだ順、新しい番号は数秒揺れる）、「焼いています」の番号（番号順、自分の番号は白で目立たせる）、最近の平均待ち時間（「注文から受け取りまで平均 約◯分」）
- 呼び出し中がない時間は、キャラクターと「いらっしゃいませ！」／「いっしょうけんめい焼いています！」
- 並び順：自分の番号 → ミニゲーム（目立つ赤いカード。たいやきくん・「ゲームであそぶ」ボタン・今日のランキング）→ お呼び出し中 → 焼いています。焼き待ちの間は、自分の番号のカードにも「待っている間に、ミニゲームであそぶ」ボタンを出す。メニューは載せない（屋台のメニュー表で見てもらう）
- 「最終更新 ◯秒前」を表示し、60秒以上更新がなければ「お店の呼び出し表示もご確認ください」と出す
- データの流れ：レジPCの `npm run public-sync` が3秒ごとに `/api/orders?status=waiting,ready` と `/api/summary` を読み、変化があったとき（なくても15秒ごと）に番号と待ち時間の目安（平均待ち時間・完成のペース）だけをクラウドへ PUT する
- クラウドの API：`GET /api/status?n=` は誰でも読める。`PUT /api/status`（body: `{ ready: number[], waiting: number[], avgWaitSeconds: number | null, secondsPerOrder?: number | null }`）は `Authorization: Bearer <PUSH_TOKEN>` が必要
- `prefers-reduced-motion` のときはアニメーションを止める
- **ミニゲーム「およげない？たいやきくん」**（`cloud/public/game.js`、外部ライブラリなし）
  - タップで少し浮かぶ（泳げないので放っておくと沈む）。上の網・下の岩をよけると1点、浮き輪は3点、たまに出る金の浮き輪は10点。ぶつかるか底に沈んだら終わり
  - 10個よけるごとにステージが変わる：浅瀬（網と岩だけ）→ サンゴ礁（すき間が上下に動く）→ 深海（クラゲが漂う）→ 嵐の海（全部入り・雨と稲光）。4つめの次は「2周目」として景色が浅瀬に戻り、どの景色でも動くすき間とクラゲが出る。速さとすき間の狭さは、よけた数だけで決まり（一周しても遅くならない）、上限まで上がり続ける。景色の色はなめらかに切り替える
  - たいやきくんは、ロゴの絵からたい焼きの形（はちまき・しっぽまで）だけを切り抜いた絵（`cloud/public/brand/taiyaki.webp`、`npm run assets` で作る）。ロゴでは波と浮き輪に隠れているしっぽの右下は、しっぽの上半分の鏡写しで補う。進み具合のバーで泳ぐ絵も同じ
  - 稲光は `prefers-reduced-motion` のときは出さない
  - アイテム（すき間に浮かぶ）：**あんこだん**（5秒間あんこを自動で撃つ。クラゲを倒すと＋5、しびれだまも撃ち落とせる。クラゲが出る海だけに出る）、**あおいうきわ**（シールド。1回だけ当たっても・沈んでも助かる）
  - **クラゲの反撃**：クラゲが出る海（しんかい・あらしのうみ、2周目以降は全部）では、近づいたクラゲがたいやきくんに向けてしびれだまを1回撃ってくる
  - 左上に、シールドとあんこだんの残り時間を出す
  - **ボスクラゲ**：あらしのうみを10個よけきると登場（「ボスクラゲ あらわる！」）。ボス戦のあいだは網と岩が出ず、あんこだんが撃ち放題。ボスは上下に動きながら、しびれだま3方向とこクラゲ2ひきを交互に出してくる。体当たりもアウト。あんこだん1発＋2、倒すと＋30（体力は 8＋周回×4）。20秒で倒せないと「にげられた…」。どちらでも次の周へ進む
  - **子どもも大人も楽しめるように**：ゲームまわり（カード・説明・結果）は丸くて太い文字（M PLUS Rounded 1c、使う文字だけ切り出し）と、ひらがな中心の分かち書き（行はことばの間でだけ折り返す）。幼すぎる言い方はしない
  - 遊び方は絵で見せる（うきわ＋3てん・きんのうきわ＋10てん・あみ／いわ／クラゲに あたると おわり）。「はじめる！」のあとは、最初のタップで泳ぎ出す（読み終えてから自分のタイミングで始められる）。難しさは変えない
  - 結果にひとこと（「じこベスト こうしん！」「おしい！ あと ◯てんで じこベスト」「ナイス！」など）。ランキング登録のエラーもひらがなでやさしく
  - 遊んでいる間に自分の番号ができあがったら、ゲームを止めて「できあがり！」を出す。別のアプリに切り替えたらその回は終わり
  - **ランキング**（上位10人。タブで「きょう」＝日本時間の日ごと／「れきだい」＝これまでのプレイヤーごとの最高点／「寮祭の日」＝当日の最終結果）：だれでも（整理券がなくても、どのURLから開いても）名前（1〜10文字）をつけて登録できる。スマホごとに自動で作るID（`localStorage`）で見分け、1台につき最高点1件、名前はいつでも変えられる。表示・削除にはIDの先頭6文字だけを使う（IDそのものは出さないので他人の記録は書き換えられない）
  - 登録のチェック：不適切な言葉を含む名前は断る（`src/lib/ranking.ts` の一覧。「カスタード」などを巻き込まない語だけ）、遊んだ時間に対してありえない点数（1秒あたり12点＋20点を超える）は断る、同じ回線（`CF-Connecting-IP`）からの登録は10分に20回まで
  - 登録は「きょう」と「れきだい」の両方に入る（結果に両方の順位を出す）。れきだいは、日ごとのランキングから作る
  - スタッフは `npm run ranking`（`-- all`・`-- event`・`-- 2026-10-04` も）で全員分（IDつき）を見て、`npm run ranking -- remove a1b2c3` で、きょう・れきだい・過去の日すべてから消せる
- **営業終了の表示**：`npm run closing -- on 寮祭の日付` で、番号まわり（あなたの番号・お呼び出し中・焼いています）を隠してお礼を出す。ミニゲームとランキングはそのまま使え、記録も伸ばせる（さいしょは「れきだい」を表示）。切り替えるとき、寮祭の日とれきだいのランキングを `backups/` にJSONで保存。`-- off` で戻す
  - API：`GET /api/ranking`（上位10人）、`POST /api/ranking`（`{ player, name, score, playMs }`）、`GET /api/ranking?board=today|all|event`、`GET /api/config`（営業終了・寮祭の日付）。`GET /api/ranking?all=1&board=`・`DELETE /api/ranking?tag=`・`PUT /api/config`（合言葉が必要）

### 6.6 置きっぱなしの画面（レジ・キッチン・呼び出し表示）
- 画面が消えないようにする。http の LAN では Wake Lock API が使えないため nosleep.js（使えれば Wake Lock、なければ無音の動画を流し続ける）を使う
- ブラウザの決まりで最初に1回タップが必要なので、まだのときは画面下に「画面をどこか1回タップしてください」と出す。キッチンの音もこのタップで鳴らせるようになる
- 別のアプリから戻ってきたら、かけ直す

### 6.7 練習モード
- `npm run practice` で起動すると、毎回まっさらな練習用DB（`data/practice.db`）を使う。お客さん向けページへの送信と自動バックアップはしない
- すべての画面の上に「練習モード：ここでの注文は本番のデータに残りません」の帯を出す（`/api/server-info` の `practice`）

## 7. API
| メソッド | パス | 内容 |
|---|---|---|
| POST | `/api/orders` | 注文作成。body: `{ items: { flavor, qty }[] }` → `{ id, number, amount, tickets }` |
| GET | `/api/orders?status=waiting,ready` | 注文一覧（items込み） |
| PATCH | `/api/orders/:id` | 状態変更。body: `{ status }`。不正遷移は 409 |
| GET | `/api/summary` | 5章の集計一式 |
| GET/PUT | `/api/settings` | 目標（`{ targetQty }`） |
| GET | `/api/export.csv` | 全注文CSV（1行＝1注文、味別個数を列に） |
| GET | `/api/server-info` | LAN上のIPアドレスとURL |

## 8. 非機能要件
- 外部リソースへの通信ゼロ（フォントはシステムフォント）。例外は 6.5 の `public-sync` が番号を送ることだけで、止まっても営業に影響しないこと
- 5台程度からの2秒ポーリングで問題なく動くこと
- サーバー再起動後もデータが残ること
- スマホ縦画面（/display・/admin）とPC横画面（/register・/kitchen）に対応
- 認証なし（ローカルネットワーク限定のため）
